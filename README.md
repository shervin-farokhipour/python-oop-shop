# فروشگاه با پایتون | Python OOP Shop

پروژهٔ کلاسی برنامه‌نویسی شیءگرا با رابط گرافیکی **Tkinter** برای مدیریت خریداران، محصولات و سفارش‌ها.
کلاس‌ها، رابط، اعتبارسنجی و ذخیره‌سازی از هم جدا هستند. اطلاعات خریداران و محصولات در فایل متنی ذخیره می‌شوند.

## امکانات

- ثبت، جستجو، ویرایش و حذف خریداران
- ثبت و نمایش محصول، قیمت واحد، موجودی، دسته‌بندی و فروشنده
- ساخت سفارش برای خریدار ثبت‌شده و افزودن چند ردیف محصول
- نمایش تعداد خرید، مبلغ هر ردیف و جمع کل سفارش
- بررسی کافی بودن موجودی و جلوگیری از پرداخت دوباره
- پرداخت آزمایشی و ذخیرهٔ موجودی جدید

## پیش‌نیازها

- Python 3؛ برنامه روی **Python 3.11 در Windows** آزمایش شده است.
- Tkinter؛ معمولاً همراه نصب Python در Windows در دسترس است.
- کتابخانهٔ جانبی، دیتابیس و اتصال اینترنت برای اجرای برنامه لازم نیست.

برای بررسی نصب Tkinter این دستور را اجرا کنید؛ باید یک پنجرهٔ آزمایشی باز شود:

```bash
python -m tkinter
```

## دریافت و اجرا

### روش ساده با PyCharm

1. در صفحهٔ مخزن، **Code → Download ZIP** را انتخاب کنید.
2. فایل ZIP را استخراج کنید.
3. پوشه‌ای را که `main.py` داخل آن است در PyCharm باز کنید.
4. مفسر Python را انتخاب و `main.py` را اجرا کنید.

### روش ترمینال با Git

```bash
git clone https://github.com/shervin-farokhipour/python-oop-shop.git
cd python-oop-shop
python main.py
```

اگر پروژه را با ZIP دریافت کرده‌اید، ترمینال را در پوشهٔ استخراج‌شده، کنار `main.py` باز کنید و فقط دستور آخر را اجرا کنید.

## یک نمونهٔ استفاده

1. در زبانهٔ «خریداران»، اطلاعات زیر را وارد کنید و «ثبت» را بزنید:

| فیلد | مقدار نمونه |
| --- | --- |
| شناسه | `1` |
| نام | علی |
| نام خانوادگی | احمدی |
| ایمیل | `ali@example.com` |
| رمز آموزشی | `Sample123` |
| موبایل | `09123456789` |
| آدرس | تهران |

2. در زبانهٔ «محصولات و سفارش»، «به‌روزرسانی خریداران» را بزنید.
3. خریدار را انتخاب کنید و «شروع سفارش جدید» را بزنید.
4. محصول «دفتر» را انتخاب، تعداد را `2` وارد و به سفارش اضافه کنید.
5. با قیمت نمونهٔ ۵۰٬۰۰۰ تومان، جمع سفارش ۱۰۰٬۰۰۰ تومان می‌شود.
6. با زدن «پرداخت آزمایشی و کاهش موجودی»، موجودی دفتر از ۲۰ به ۱۸ می‌رسد.

این مثال قیمت و موجودی اولیهٔ فایل نمونه را فرض می‌کند. هیچ پول واقعی جابه‌جا نمی‌شود.

```text
├── storage/               # خواندن و نوشتن فایل‌ها
├── view/                  # فرم‌های Tkinter
├── data/                  # فایل‌های داده
├── docs/                  # راهنمای فارسی و دیاگرام
└── tests/                 # آزمون‌های برنامه؛ جدا از اجرای معمول
```

## منطق شیءگرایی

`Buyer` و `Seller` از `User` ارث می‌برند. هر `Product` به دسته‌بندی و فروشنده متصل است.
هر `Order` یک خریدار، لیستی از `OrderItem` و یک پرداخت اختیاری دارد.

getter و setter ویژگی‌های قابل تغییر داخل خود کلاس هستند و setterها توابع فایل جداگانهٔ
`validation/validation.py` را صدا می‌زنند. `OrderItem.product` فقط یک شیء `Product` می‌پذیرد.
`Order.total_price` فقط getter دارد؛ جمع با یک حلقه از روی ردیف‌ها محاسبه می‌شود و مستقیم قابل تغییر نیست.

## ذخیره‌سازی و محدودیت‌ها

- محصولات، قیمت و موجودی در `data/products.txt` ذخیره می‌شوند.
- `data/buyers.txt` با اولین ثبت خریدار ساخته می‌شود و برای جلوگیری از انتشار اطلاعات شخصی در Git نادیده گرفته می‌شود.
- رمز در فایل آموزشی به شکل متن ذخیره می‌شود؛ از رمز واقعی استفاده نکنید. برنامه سامانهٔ ورود کاربران ندارد.
- سفارش و پرداخت فقط در حافظهٔ اجرای فعلی هستند؛ با بستن برنامه پاک می‌شوند، اما موجودی پرداخت‌شده ذخیره می‌ماند.
- فروشنده و دسته‌بندی فعلاً ثابت‌اند. ویرایش و حذف محصول و تاریخچهٔ سفارش پیاده‌سازی نشده‌اند.
- برنامه برای اجرای یک نمونه در یک زمان طراحی شده است؛ پرداخت آنلاین و مدیریت هم‌زمانی ندارد.

## آزمون‌ها

از پوشهٔ اصلی پروژه اجرا کنید:

```bash
python -m unittest discover -s tests -v
```

آزمون‌ها از فایل‌های موقت استفاده می‌کنند و اطلاعات اصلی را تغییر نمی‌دهند.
آزمون‌های فرم به Tkinter و محیط گرافیکی نیاز دارند. ذخیره‌سازی، عملیات خریداران، ثبت محصول،
موجودی، پرداخت دوباره، خریدار حذف‌شده، اعتبارسنجی محصول و محاسبهٔ جمع سفارش بررسی می‌شوند.
